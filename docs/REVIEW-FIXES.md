### CI 抓到的真问题：浅色主题从未被审计过

推送后 GitHub Actions 在 Ubuntu 上失败（本机 Windows 全绿），原因是**两边的系统主题不同**：
开发机是深色，CI runner 是浅色，而 axe 之前只跑一套主题（跟随系统），浅色那半边从来没被测过。

实测出来的对比度（WCAG AA 要求 4.5:1）：

| 元素 | 浅色下的对比度 | 原因 |
|---|---|---|
| `.callout.info` / `.warn` / `.ok` | **1.25–1.40** | 只写了深色主题的浅色文字（#bcd7f8 / #f3d9a4 / #b3efd4），白底浅字基本不可读 |
| `.plist li` | **1.64** | 硬编码 #c3cadb（深色专用） |
| `.foodtag.乳品` | **1.47** | 同上（#c3cadb 叠浅灰底） |
| `.lv.入门` / `.lv.高阶` | 3.30–4.08 | 用 --ok / --orange 直接压在淡色底上 |
| `.genm > b` | 4.3 | --acc 压在 --bg2 上 |

修复：给这些类补 `body.light` 变体（每一条颜色都先算过对比度再写），并让 axe **每页跑深色 + 浅色两轮**（`?theme=` 参数），`a11y-run.html` 输出 `themeActual` 证明主题真的生效了——否则两轮跑出一样的数字也没人会发现。

同时修掉两条「依赖系统主题」的冒烟断言：`可切回深色` → `可切回原主题`（比较切换前后），日历描边断言从「边框色含 198」改为「描边可见且与背景不同」。

这一步的价值不是修了 5 个颜色，而是**发现「本地全绿 ≠ 真的没问题」**：只要审计环境跟着系统主题走，另一半永远是盲区。
